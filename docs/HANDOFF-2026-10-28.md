## SDD ledger (rulings + deferred items) for Stream 2

Key rulings I made on your behalf (review these — rework if any is wrong):
- **Task 2 `package:` identity:** the plan wrote `.product(name:"SunbayCheckout", package:"SunbayCheckout")`,
  but SwiftPM derives a PATH dependency's identity from the directory name. The SDK repo root dir is
  `ios`, so the correct form is `.product(name:"SunbayCheckout", package:"ios")`. Both reviewers confirmed
  no strictly-better form exists (`.package(name:path:)` is deprecated in tools 5.9). Cost if wrong: the
  smoke build breaks loudly if the repo is checked out under a different directory name — inherent to
  SwiftPM path deps, documented inline. **(This is the one item most worth your eyes.)**
- **Task 3 xcframework not actually produced:** `scripts/build-xcframework.sh` is correct and fails LOUDLY
  (exit 1), because a pure-SwiftPM *library* scheme archives to a `.o`, not a `.framework`, on any machine.
  Producing a real binary requires wrapping the SDK in a framework target — that is the recorded **C3**
  future step (after real backend + API freeze + official release). The script, `docs/releasing.md`, and a
  commented `.binaryTarget` skeleton in `Package.swift` are the no-rework bridge to C3.
