# iOS i18n, Example App & E2E Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a localization subsystem (`en-US` + `zh-CN`) to the SDK, a real Tuist-generated Example app with a configuration playground, and a protocol-driven end-to-end XCTest target.

**Architecture:** Localization is an internal subsystem (resolver → `Bundle.module` lookup → helper) consumed by the UI layer and an error/amount formatter, keeping Core UI-agnostic and the public API shape stable. The Example app becomes a real Xcode app (declarative `Project.swift`, generated project git-ignored) so real-device Apple Pay and entitlements are possible. E2E tests drive the `CheckoutController` protocol boundary with scriptable mocks — no simulator, no XCUITest.

**Tech Stack:** Swift 5.9, SwiftPM (`resources`/`defaultLocalization`), `Localizable.strings`, `NumberFormatter`, XCTest, Tuist.

**Spec:** `docs/superpowers/specs/2026-10-27-ios-i18n-demo-e2e-design.md`

## Global Constraints

- Swift only; min iOS target `.iOS(.v15)`; follow Apple official APIs.
- English only in all code and repo docs: comments, identifiers, string literals, test names, commit messages. (Localized `.strings` values are the sole place non-English user copy lives; `zh-Hans` values are Chinese by definition.)
- Language codes exposed on the public API use BCP-47 region form: `en-US`, `zh-CN`. `.lproj` directory names use Apple identifiers: `en`, `zh-Hans`.
- v1 ships `en-US` + `zh-CN` only (Simplified Chinese).
- Never log/persist/return card values, wallet tokens, COF secrets, or the RSA payload. Localization touches only static chrome and code-derived error text.
- Core (`CheckoutController`, `Sources/.../Core`) imports no UIKit/PassKit.
- Backend services stay behind `PaymentService`/`CofService` protocols; scriptable mocks live in tests only.
- Git: stage specific files by name; no merchant certs/keys; placeholder merchant id only; generated `.xcodeproj` is git-ignored. Commit only the declarative `Project.swift`.
- `swift test` must pass after every task.

## Review Focus

- **Unknown / malformed language code** (e.g. `"fr-FR"`, `"xx"`, `""`): resolver must fall back (specific→general→`en-US`), never crash or return an empty bundle. Pinned in Task 2.
- **Missing localization key at runtime**: `SunbayLocalizedString` must return a sensible value (the key or a dev default), never an empty string, when a `.strings` entry is absent. Pinned in Task 1.
- **Zero / large / non-USD minor-unit amounts** (e.g. `0`, JPY with 0 decimal places, a large `Int64`): `AmountFormatter` must produce a correctly scaled localized string using the currency's real fraction digits, not a hardcoded /100. Pinned in Task 4.
- **Error code with no mapping entry**: the error localizer must fall back to the error's existing `message` (developer string) rather than return empty, so an unmapped future code still surfaces something. Pinned in Task 5.
- **`locale == nil` on configuration (the default today)**: resolution must proceed to system language then `en-US` with no behavior regression for existing callers. Pinned in Task 2.

  - `func resolvedBundle() -> Bundle` — returns the `.lproj` sub-bundle of `Bundle.module` for the resolved language, or `Bundle.module` itself as the `en` default.
